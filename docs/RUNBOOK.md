# Runbook

## 0. Prerequisites

- Python 3.10+ (the package uses only the standard library).
- Moomoo app + Moomoo CLI (`~/.moomoo/bin/moomoo`) for live reads and paper orders.
- Qoder desktop for local runs; Qoder Cloud Agents for the scheduled multi-agent loop.

Nothing here places an order by itself. OAuth is a manual step owned by the user.

## 1. Verify the package (2 minutes, no credentials)

```bash
cd qoder-submission/agent
python3 -m unittest discover -s tests -v
python3 -m leadguard demo
open ../dashboard/report.html
```

Expected: 9 tests pass; four decisions (`RECONCILE`, bounce `BUY_CALL_SPREAD`,
breakdown `BUY_PUT_SPREAD`, chop `HOLD`); report shows NAV $158,740.37 and the
reconcile warning.

## 2. Reconcile the account (mandatory before any new trade)

1. Open the sim account. Confirm whether the NVDA 11-20 172.50 put produced a
   **short stock position** (auto-exercise). If yes, buy to cover.
2. Confirm the AMD 11-20 462.50C is gone (expired worthless).
3. Screenshot the position list and cash. Update
   `agent/fixtures/account_2026-11-20.json` only with verified values and set
   `verified: true` on each real position — never just to pass the gate.

The agent refuses new risk until this is done. That is the point.

## 3. Configure the live path (once)

```bash
~/.moomoo/bin/moomoo config init          # user runs this and completes OAuth
~/.moomoo/bin/moomoo sim account list --format json
```

Copy the sim account id into `agent/config/competition.json` → `account_id`. Keep
`mode: dry_run` until you are ready to place paper orders.

Then:

```bash
cd agent
python3 -m leadguard live --mode dry_run
```

If it prints quotes and a HOLD/RECONCILE decision, the read-only path works.

## 4. Session calendar (ET and SGT)

SGT = ET + 13h in November.

| Session | ET | SGT (next day) | What runs |
| --- | --- | --- | --- |
| Monday open check | 09:45 | Tue 22:45 | First evaluation; reconcile or bounce/breakdown |
| Monday mid | 12:30 | Tue 01:30 | Re-check confirmation; manage entries |
| Monday close | 15:30 | Tue 04:30 | No new entries after this |
| Tue / Wed same slots | 09:45 / 12:30 / 15:30 | +13h | Same routine |
| Wed cutoff | 13:00 | Thu 02:00 | Last moment for a new position |
| Thu 26 Nov | — | — | US market closed (Thanksgiving) |
| Fri 27 Nov flatten | 12:30 | Sat 01:30 | Close everything, log the final state |

Manual alternative: run `python3 -m leadguard live --mode dry_run` at each slot.
Automated alternative: a Qoder Cloud Agent session or a local scheduler that runs
the same command and appends to the log.

To run a session, mount this package as a resource: either push the folder to a
GitHub repo and attach it as `github_repository`, or upload the package as a file
resource. Then start a session on the Coordinator. Sessions default to ask-before-
Bash, so the Executor cannot place an order without an explicit approval.

For live Moomoo tools inside a cloud session, create a **Vault** in the Cloud
Agents console (Forward Mode → Vault → Create), add Moomoo as a custom MCP with
credential type **MCP OAuth** and server URL `https://mcp.moomoo.com/mcp`, then
complete the Moomoo OAuth screen. Attach that vault to the session; without it the
session simply has no Moomoo tools. Skill upload: `qoder/leadguard.zip` (one
top-level `leadguard/` folder with `SKILL.md`) via Cloud Agents → Skills → Create
Skill. Scheduled runs use Forward Mode; a 09:45 America/New_York weekday schedule
matches the ET checkpoints above.

The handbook for these steps is at
https://moomoo-qoder-challenge-rgkelnyuzbm.qoder.website/.

Local Qoder usage is the other half of the rubric: `demo`, `report`, and the HTML
report are generated by the local agent (this session), and the Cloud team runs
the same prompts in `agent/prompts/`.

## 6. Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| `期权失效,请交易有效期内的期权` on a sell | Contract expired (11-20 expiry, now 11-21 SGT) | Nothing to sell; the position was auto-exercised. Check for short stock |
| CLI says `not logged in` | OAuth not completed | `moomoo config init`, user completes login |
| CLI says `client_id is not configured` | First-run config missing | Same as above |
| Report shows "risk gate: blocked" on HOLD | Old report | Regenerate: `python3 -m leadguard report` |
| Demo debits look too cheap for a VIX-36 tape | Fixtures are illustrative | Replace with live spread quotes before execution |
